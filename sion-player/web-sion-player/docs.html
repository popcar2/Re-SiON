A small player for SiON MML music. Give it MML text and it renders stereo audio. It has no dependencies and is no_std, so the same code runs as a Rust crate, as WebAssembly in the browser, and as a C library.

  • Output: interleaved stereo f32 (left, right, left, right…) at 44,100 Hz.
  • One frame is one left/right pair, so 44,100 frames are one second.
  • The MML language itself is described in the SiON MML reference manual. MML support below lists what this player implements and where it differs.

Quick start

Every interface works the same way: create a song from MML, then ask it for audio a block at a time until it says it has finished.

Rust

[dependencies]
sion = { path = "../sion" }
use sion::{Song, RATE};

let mut song = Song::new("t120 %5@0 l8 cdefgab<c;");
let mut buf = vec![0f32; 2 * 1024]; // 1024 frames
while song.render(&mut buf) {
    // buf holds 1024 stereo frames at RATE Hz: send them to your audio output.
}

JavaScript (browser, Node, Deno)

Copy sion.wasm and sion.js next to your page.

import { Sion } from "./sion.js";

const sion = await Sion.load(fetch("sion.wasm"));
const song = sion.song("t120 %5@0 l8 cdefgab<c;");
const buf = new Float32Array(2 * 1024);
while (song.render(buf)) {
  // play buf (interleaved stereo, sion.rate Hz)
}
song.free(); // songs live in wasm memory: free them when done

C / C++

Link against libsion.so (Linux) or sion.dll (Windows) and include sion.h.

#include <string.h>
#include "sion.h"

const char *mml = "t120 %5@0 l8 cdefgab<c;";
SionSong *song = sion_song_new(mml, strlen(mml));
float buf[2 * 1024];
while (sion_song_render(song, buf, 1024)) {
    /* play buf (interleaved stereo, sion_rate() Hz) */
}
sion_song_free(song);

How playback works

Rendering. Each render call fills the buffer and moves playback forward by that many frames. Any buffer size works. Samples are clamped to -1..1.

Declicking. A key-on, volume change or pan change can make a track's output jump in the middle of a wave: a waveform restarting from its first frame, or a hard pan flip. As in trackers, such a jump is smoothed over: the output picks up where it would have been without the change, and the difference fades out over about a millisecond. On a key-on, or when the volume comes up from silence, only the old level fades out, so attacks stay sharp. Everything else is exactly SiON's output, and so is any track that no such change touches.

Ending. render returns false once every track has ended and the output has been silent for half a second, so release tails are not cut off. A song with a $ loop point never ends: stop it yourself.

Length. length measures one pass through the MML, in frames, without rendering any audio. One pass ends when every track has either finished or jumped back to its $ once. It is capped at one hour. Release tails are not included.

Looping. For a song with $, loop_start gives the frame playback returns to after length frames. Use both to show a loop region or to seek within a looping song.

Seeking. skip(frames) moves forward without producing output. It jumps from event to event instead of synthesizing every sample, so it is fast even for long songs. The result is close to, but not exactly, what continuous playback gives: echoes from before the last quarter second are missing, and vibrato phases drift. To seek backwards, create a new song and skip from the start.

Following along. notes() gives, per track, the byte offset in the MML text of the note playing now (-1 for a rest or an ended track). Use it to highlight the playing notes in an editor. It needs the spans feature (always on in the WebAssembly build).

PCM samples. Modules %7 and %10 play recorded samples. Embed them in the MML with #PCMB, or set them from code with set_sample, which replaces any #PCMB of the same number. #PCMWAVE, #PCMVOICE and #SAMPLER build instruments and drum kits out of them (see Sample instruments and drum kits).

MML support

This section is a summary. For each command's full meaning and parameters, see the SiON MML reference manual.

Structure

  • Statements end with ;. Each statement that does not start with # is one track. All tracks play at once.
  • Comments: // to end of line and /* block */.
  • Unknown commands are skipped, so MML written for full SiON still plays, minus the parts this player lacks.

Envelope tables

Define a table with #TABLEn{...}, then apply it per step to a note:

CommandApplies the table to
naAmplitude.
ntNote (in semitones).
npPitch (in 1/64 semitones).
nfFilter cutoff.
@@Tone number.

Prefix with _ (_na) for the release part of the note. na values set the expression (x, 0..128) itself; !na adds them to the track's x. A table can also be written inline: na{0,8,16}. Table syntax supports (a,b)n interpolation, [...]n repeats, a | loop point and a *scale+offset suffix.

As in SiON, a table's first value applies at the key-on (or key-off, for _ tables) and each next one an envelope frame later (#FPS, @fps: 735 samples at the default 60), and values are read as (int)(v + 0.5), so a negative value comes out one higher (-10 plays as -9; write -11 for -10).

Sample instruments and drum kits

#PCMB holds the audio. These three statements say how to play it, and refer to a #PCMB by its number, so one sample can be used by several instruments without being stored again. They can come before or after the #PCMBs they use. Arguments can be left out (#PCMWAVE0{3,,0,59}): each one has a default.

#PCMWAVEn{sample,note,from,to,channels,start,end,loop} gives %7 instrument n (0..255) a sample for a range of keys. Several of them with different ranges make one instrument play different samples on different keys (a multisample), and switching between them needs no @n:

ArgumentMeaning (default)
sampleThe #PCMB number.
noteThe note at which the sample plays at its #PCMB rate (the #PCMB's key). Fractions are allowed.
from, toThe keys that play it (0, 127). to -1 means just from. Keys outside every range are silent.
channelsIgnored: samples are mono.
start, endThe first frame, and the frame to stop before, counted in the #PCMB (all of it).
loopThe frame to loop from, counted in the #PCMB (the #PCMB's own loop). -1: no loop. Below -1, such as -500: loop the last 500 frames.

#PCMVOICEn{volume note,volume range,volume amount,pan note,pan range,pan width,ar,dr,sr,rr,sl}commands sets how instrument n plays:

  • Volume key scaling (64, 0, 0): over range keys centered on note, the level rises by amount / 128. Keys below the range are that much quieter, keys above are at full level. A negative amount turns this around.
  • Pan key scaling (64, 0, 0): over the same kind of range, pan moves from -width / 2 to +width / 2, added to the track's pan. A width of 128 spreads the keys from left to right.
  • ar, dr, sr, rr, sl (63, 0, 0, 63, 0): the envelope, as in @n,ar,dr,sr,rr,sl.
  • Commands after } run each time the instrument is chosen, as they do for FM voices.

A #PCMVOICE without a #PCMWAVE plays #PCMB n on every key.

#SAMPLERn{sample,hold,pan,channels,start,end,loop} makes key n % 128 of %10 bank n / 128 play a sample, at its own rate, whatever the pitch. hold 1 plays the sample to its end after key-off (0). pan (-64..64) is added to the track's pan (0). channels, start, end and loop are as for #PCMWAVE. In a bank that has any #SAMPLER, keys without one are silent.

#PCMB0{...}22050,48;  #PCMB1{...}22050,72;   // a low and a high recording of the same instrument
#PCMWAVE0{0,,0,59};   #PCMWAVE0{1,,60,127};  // instrument 0: sample 0 below o5c, sample 1 from there
#PCMVOICE0{,,,,,,63,0,0,40,0};               // with a slower release
#PCMB2{...}; #PCMB3{...};
#SAMPLER36{2}; #SAMPLER38{3,1};              // kit: kick on o3c, snare on o3d (playing on through key-off)
%7@0 l8 o4 cegb<ceg;
%10 l8 o3 cdcd;

Differences from SiON

Additions:

  • #PCMBn{data}rate,key,loop,flags,level embeds a PCM sample in the MML text. data is base64url of signed little-endian samples: 8-bit, or 16-bit with flags 1. Flags 2 loops back and forth. Flags 4 decodes NES DPCM starting from level. {=m} reuses the data of earlier DPCM sample m. Defaults: rate 44100, key 60, no loop.
  • @ph on PCM modules takes a fractional or negative start frame and a play length.
  • k accepts fractions.

#SAMPLER, #PCMWAVE and #PCMVOICE use SiON's names and arguments, with one difference: where SiON expects the name of a sound, they take a #PCMB number. In SiON these statements hold no audio. The braces name a sound that the program running SiON loaded and registered under that name. An MML file can't carry the sound, so a song that uses them only plays inside that program. Here the audio is in the file, in #PCMB, and these statements point at it, so the whole song is one MML file. (In SiON, registering sounds under the names 0, 1, … would make the same text work.) The rest differs only in small ways:

  • Without a note, #PCMWAVE uses the #PCMB's own key, because #PCMB already says what pitch the sample is at. SiON's default is 69 (o5a). Fractional notes are allowed.
  • A left-out start is the first frame and a left-out end is the last. SiON skips quiet frames at the start and end by itself.
  • A left-out loop keeps the #PCMB's loop. A tail loop (below -1) doesn't crossfade.
  • channels is ignored, because samples are mono.
  • %7 has 256 instruments (SiON has 128).

Playback differs in one way: jumps from key-ons and volume and pan changes are smoothed over (see Declicking).

Not supported: event triggers (%t, %e), which are skipped.
